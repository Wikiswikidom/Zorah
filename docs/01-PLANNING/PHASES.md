# Phase Definitions

Each phase has four gates: planned, in progress, review/testing, done.

Phase 1 is documentation-only and establishes the system of record.

Phase 2 converts the requirements into user journeys, wireframes, visual design and responsive behavior. No implementation should bypass the approved design direction.

Engineering phases are deliberately incremental: foundation → data/auth → admin → storefront → commerce → integrations → hardening → launch.

A phase may expose new requirements. Those requirements must be logged and assessed rather than silently changing architecture.
