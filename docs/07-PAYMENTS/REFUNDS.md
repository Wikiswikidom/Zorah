# Refunds

Refund policy and authorization must be finalized before production. Refunds should be initiated through the trusted server/admin workflow and recorded against the original payment and order.

Admin permissions must distinguish viewing payments from initiating refunds. Refund actions require confirmation and audit logging.

Order status, inventory effects and customer notifications must be consistent with the actual refund state. Never mark an order refunded merely because an admin clicked a UI button; provider confirmation is required where applicable.
